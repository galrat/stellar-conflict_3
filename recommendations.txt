АУДИТ ПРОЕКТА STELLAR CONFLICT — РЕКОМЕНДАЦИИ
================================================================
Дата: 2026-04-06

================================================================
[1] КРИТИЧНЫЕ БАГИ
================================================================

1.1  Соседи: квадратная сетка, а не гексагональная
     Файл: python_engine/orders_placement.py, строки 86-93
     Файл: board.py, строки 89-96

     В board.py neighbors() использует 4 соседа (квадратная сетка):
       [(0,1), (0,-1), (1,0), (-1,0)]

     Но в orders_placement.py get_available_tiles() использует 6 соседей:
       [(1,0), (-1,0), (0,1), (0,-1), (1,-1), (-1,1)]

     РЕШЕНИЕ: Использовать те же 4 направления что в board.py,
     или импортировать board.neighbor_keys() напрямую.

1.2  Нет проверки лимита приказов (8 шт на игрока)
     Файл: python_engine/orders_placement.py, функция validate_order_placement()

     Игрок может разместить больше 8 приказов, т.к. нет проверки:
       if current_state['ordersPlaced'][player_id] >= 8:
           return False, "Все приказы уже размещены"

     РЕШЕНИЕ: Добавить проверку в validate_order_placement().

1.3  ordersPlaced не инициализируется при init_game
     Файл: game_server.py, функция init_game()

     Если state из JS не содержит 'ordersPlaced', код упадет при
     попытке увеличить счетчик.

     РЕШЕНИЕ: Добавить в init_game():
       if 'ordersPlaced' not in _active_game:
           _active_game['ordersPlaced'] = [0, 0]

================================================================
[2] НЕСООТВЕТСТВИЯ ИМЁН
================================================================

2.1  Имена фаз: дефис vs подчеркивание
     game_state.py (Phase enum):    "order_placement" (подчеркивание)
     game_engine.html (JS):         "order-placement" (дефис)
     game_server.py (проверки):     "order-placement" (дефис)
     orders_placement.py:           "play-orders"     (дефис)

     ТЕКУЩЕЕ СОСТОЯНИЕ: game_server.py и JS используют дефисы — это
     работает. Но game_state.py enum НЕ совпадает.

     РЕШЕНИЕ: Либо обновить enum в game_state.py на дефисы,
     либо везде перейти на подчеркивания. Главное — единообразие.

2.2  Поле "color" vs "faction_color" в state
     Файл: current_state.txt — всё ещё содержит "color": "c1"
     Файл: game_server.py — при init_game добавляет "faction_color"

     JS может продолжать смотреть на "color" в некоторых местах.

     РЕШЕНИЕ: При init_game удалять старое поле 'color' из state:
       p.pop('color', None)

2.3  owner vs player в разных контекстах
     orders (на карте):       "owner": 0
     troops (в областях):     "player": 0
     hand_orders:              "owner": 0
     game_state.py Order:     "player_id": 0

     РЕШЕНИЕ: Выбрать одно имя и использовать везде.
     Рекомендация: "owner" для всего что на карте.

[5] ПРОПУЩЕННЫЕ ПРОВЕРКИ
================================================================

5.1  Нет проверки границ player_id
     Файл: python_engine/orders_placement.py, строки 117, 154

     player_id может быть не 0 и не 1 — тогда IndexError.

     РЕШЕНИЕ: Добавить проверку:
       if player_id not in (0, 1):
           return False, "Некорректный ID игрока"

5.2  Нет проверки что текущий игрок = запрашивающий игрок
     Файл: game_server.py, place_order_endpoint()

     Игрок может отправить запрос с чужим player_id и разместить
     приказ за другого игрока.

     РЕШЕНИЕ: Добавить проверку:
       if request.player_id != _active_game.get('curP'):
           return error("Не ваш ход")

5.3  Нет валидации snapshot при загрузке
     Файл: game_server.py, _load_temp_snapshot()

     Загруженный JSON не проверяется на корректность.
     Если файл повреждён — state станет невалидным.

     РЕШЕНИЕ: Добавить минимальную проверку (наличие ключей
     players, map, phase).

[6] АРХИТЕКТУРНЫЕ РЕКОМЕНДАЦИИ

6.1  Перенести логику соседей в board.py
     Сейчас orders_placement.py дублирует логику из board.py.

     РЕШЕНИЕ: Добавить в board.py статический метод
     neighbor_keys_from_map(map_data, tile_key) который возвращает
     ключи соседних плиток используя данные из state.

     Сейчас init_game() в game_server.py добавляет поля по одному.
     Легко забыть новое поле.

     РЕШЕНИЕ: Создать функцию ensure_state_fields(state) которая
     гарантирует наличие ВСЕХ необходимых полей:
       - dropped_orders
       - order_placed_this_turn
       - ordersPlaced
       - orders
       - faction_color для каждого игрока
       - warpStorms[].status

6.3  _save_current_state() вызывается без блокировки
     Файл: game_server.py, строка 111

     Функция пишет в файл без _game_lock.
     Вызывается только из locked-контекстов, поэтому безопасна,
     но лучше задокументировать это требование.
