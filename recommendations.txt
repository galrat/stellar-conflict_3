2. ПОТЕНЦИАЛЬНЫЕ ОШИБКИ И ЗАГЛЮЧИ
───────────────────────────────────────────────────────────────────────────────

🔴 КРИТИЧНЫЙ: Отсутствие валидации при загрузке (game_engine.html:563)
   Функция loadGameFile() просто делает Object.assign(G, data.state)
   Проблемы:
   • Если структура сохранённого файла устарела (в будущем), игра может заглючить
   • Отсутствуют проверки обязательных полей
   • Нет проверки типов данных
   → ДОБАВИТЬ валидацию с версионированием:
      - Добавить поле "version":1 в makeState()
      - В loadGameFile() проверить наличие version и вызвать миграцию если версии не совпадают
      - Проверить наличие обязательных полей (players, map, phase, etc.)

🟡 ПРОБЛЕМА: localStorage переполнится при долгой партии
   • localStorage имеет лимит ~5MB на браузер
   • Если G содержит тысячи юнитов/тайлов, JSON станет ОГРОМНЫМ
   • Fallback при недоступности сервера попытается сохранить всё в localStorage
   → Решение:
      - Добавить проверку размера JSON перед отправкой: JSON.stringify(G).length
      - Если > 4MB, показать ошибку и предложить очистить историю
      - Либо оптимизировать сохранение (не сохранять некритичные данные)

🟡 ПРОБЛЕМА: Нет обработки ошибок при большом размере на сервере
   • game_server.py использует Flask без лимита Content-Length
   • Если пользователь отправит огромный JSON, сервер может рухнуть или зависнуть
   → Решение (в game_server.py):
      - Добавить MAX_CONTENT_LENGTH = 10*1024*1024 (10MB)
      - Добавить try-catch с проверкой размера в /api/save

🟡 ПРОБЛЕМА: Отсутствует обработка ошибок синхронизации при быстрых клик-клик-клик
   • Если пользователь быстро нажимает "Сохранить", отправляются несколько одновременных fetch()
   • Непредсказуемо, какой из них завершится первым
   • Может привести к перезаписи/потере данных
   → Решение:
      - Добавить флаг: let isSaving = false
      - Перед fetch() проверить: if (isSaving) return; isSaving = true;
      - После завершения: isSaving = false;
